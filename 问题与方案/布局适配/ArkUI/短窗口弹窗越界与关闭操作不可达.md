# ArkUI 横屏短窗口弹窗越界、内容截断与关闭按钮不可达

## Overview 总体概述

弹窗在手机竖屏能显示，横屏或分屏后顶部、正文和关闭按钮超出窗口，通常是面板高度或正文滚动没有随可用空间调整。应同时核对弹窗 API 的外层配置和自定义内容根节点，不能只给正文增加 maxHeight。

## 问题现象与适用条件

- 弹窗比窗口高，拖动也找不到关闭或确认按钮。
- 长正文被裁掉，外层看似有滚动却滚不到末尾。
- 自定义弹窗横向超出屏幕，设置 maxWidth 没有预期效果。

适用于 CustomDialog、openCustomDialog、bindSheet、Popup 等内容面板。不同宿主的宽高、锚点及键盘配置不完全相同，不把其中一个接口的参数复制给其他接口。

## 原因与判断依据

| 排查项 | 说明 |
|---|---|
| 外层尺寸 | 创建弹窗的配置可能已指定固定宽高或窗口级显示范围，内部 max 不会自动改掉外层占位 |
| 内容根节点 | 根宽度是否被长文本或固定子项撑开；父约束是否有限；是否通过绝对坐标定位 |
| 总高度 | 固定标题、正文、按钮、padding、避让加起来是否超过当前宿主空间 |
| 滚动边界 | Scroll 本身是否得到有限剩余高度，正文是否又被锁死一屏高 |
| 键盘 | 仅键盘出现时越界应同时检查弹窗自身避让配置；页面键盘模式不等于弹窗模式 |

## 解决方案

### 保留弹窗类型，先修尺寸预算

先根据本次展示宿主的可用宽高确定面板上限，扣除已有系统避让和设计边距。小窗口使用较小面板或接近全屏的呈现，大窗口可限制内容宽度；上限来自当前窗口，不使用设备物理整屏尺寸。

自定义内容采用“标题 + 可滚动正文 + 固定操作”的结构。以下片段中的面板宽高由宿主可用空间计算，构建函数沿用业务内容：

```ts
Column() {
  this.dialogTitle()
  Scroll() {
    this.dialogBody()
  }.width('100%').layoutWeight(1)
  this.dialogActions()
}
.width(this.panelWidthVp)
.height(this.panelHeightVp)
```

这要求正文内容允许滚动，panelHeightVp 确实有界；标题或按钮过高时也要调整其内容，不能指望正文收缩到负空间。弹窗控制器存在 width/height 等外层配置时，应与内容根节点一致。

### 按现有 API 选择必要调整

- 内容比较少时可按内容自然高度展示，同时设置合理上限；不为所有弹窗强行填满大屏。
- 已使用 bindSheet 时，按可用高度设置 height/detents，并保证各档正文可滚动；采用半模态是产品结构选择，不是任意弹窗越界都必须换成 bindSheet。
- 锚点 Popup 需检查锚点、可放置方向和屏边距离，不能只把面板宽度设成整窗。
- 关闭、取消和确认要保持可达。已有手势关闭不等于可以移除必要的显式关闭入口。

## 修复后检查

用最长正文、最窄和最短窗口、旋转、字号放大及键盘弹出检查。面板没有跨出宿主，正文末尾能到达，头尾操作保留；关闭后原页面输入和滚动状态不丢失。
