# ArkUI 图片拉伸、非预期裁切与宽屏占高过大

## Overview 总体概述

图片内容变形、边缘被裁和图片太高是三个不同问题。应同时核对素材宽高比、组件实际边界和 ImageFit。Cover 通常保持比例并裁边，Contain 保留全图但可能留白；改填充模式不能单独解决卡片本身过高。

## 问题现象与适用条件

- 人像、商品或图标被拉长压扁。
- 首页头图、轮播图或分享预览的重要文字被切掉。
- 展开后图片比例正常，却高得挤掉下方内容。

适用于普通 Image 及图片卡片。相机预览、视频 Surface 或图片解码方向错误需要排查相应媒体链路，不能只更改 ImageFit。

## 原因与判断依据

| 表现 | 检查方法 |
|---|---|
| 物体形状改变 | 比较源比例与组件比例，查看 Fill 或图片被预处理拉伸的情况 |
| 形状正确但边缘缺失 | 检查 Cover、裁剪区域、父容器 clip 和图片对齐；这通常是裁切，不是拉伸 |
| 图片完整但有留白 | 检查 Contain 与非同形容器；若必须全图且不裁切，留白可能是必要结果 |
| 随宽屏持续长高 | 图片按原比例铺满越来越宽的单列；应调整内容布局或高度策略，而不只是换 fit |
| 图标、文字同时放大 | 排查 lpx、基于整屏宽度的 scale/rem 换算；不要把普通宽屏尺寸变化都当系统字号问题 |

## 解决方案

### 1. 先确定图片承担的业务任务

商品缩略图可允许边缘适量裁切；海报、证件、分享预览中的完整文字通常不能裁掉；装饰性背景则可优先铺满。按照这个区别选择 Cover、Contain 或其他明确的填充策略，不能全局替换成同一种。

组件需要跟随素材比例时，比例来自素材真实宽高：

```ts
Image(this.imageSource)
  .width('100%')
  .aspectRatio(this.sourceWidth / this.sourceHeight)
  .objectFit(ImageFit.Contain)
```

该片段要求宽高均大于零；异步图片尚未获得尺寸时提供稳定占位比例，不能除以零，也不要因多次加载回调不断改变页面高度。此例不适用于要求统一卡片裁切框的缩略图。

### 2. 宽屏限制占高，不强行改变素材比例

对于统一高度的头图，可由有界容器确定展示高度，再用允许的 fit 方式放置图片。若采用高度上限，宽高关系要同步计算，不能把图片宽高各自强制设成相互矛盾的值。

同质卡片应先考虑增列，让单卡宽度合理；上图下文可在已确认方案下挪成左右排列。关键插画需要保持完整时，可减小图片区域并保留文字与按钮空间。不要把所有媒体简单等比放大到平板全宽。

放大比例或屏高占比若有产品验收要求，必须指明对比基准、测量单位和页面类型；不把某次测试的倍数阈值当作全部图片通用标准。

### 3. 单独处理单位与资源问题

常规控件尺寸使用 vp，字号按工程策略使用 fp；lpx 适用于确有统一设计宽度缩放要求的场景。若它导致功能图标随整窗无限变大，应改为明确的尺寸或断点值，而不是在另一层增加反向 scale 抵消。

## 相关方案

若图片本身比例正确，但宽屏轮播仍只显示一项、单卡过大，再读《ArkUI Swiper 宽屏仍单项、轮播拉长与边缘留白》。它处理可见数量与间距，不替代本篇的素材和裁切判断。

## 修复后检查

用横图、竖图、长图及加载失败占位检查，确认主体和文字没有意外裁切，卡片没有抖动、空隙或占高失控。分别查看宽屏与短窗口，不能只检查图片比例正确就认为布局合理。
