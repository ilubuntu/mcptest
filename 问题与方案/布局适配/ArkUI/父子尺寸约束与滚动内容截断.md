# ArkUI 父子尺寸约束错误导致内容截断、底部按钮不可达

## Overview 总体概述

页面在手机上正常，横屏、分屏或折叠后底部按钮消失，不一定是安全区或键盘问题。常见原因是头栏之外的内容又占了整页高度，或者长内容没有滚动空间。应先找出哪一层尺寸超出父容器，再调整高度分配；不能只裁剪溢出或减小字体。

## 问题现象与适用条件

- 页面右侧、底部被裁掉，登录协议、提交按钮或列表末项无法到达。
- `constraintSize` 已设置，实际内容仍超过容器。
- 列表只有一条记录，却占据接近整屏的高度。
- 底部工具栏覆盖正文，或短列表整体悬在页面中间。

适用于 ArkTS 中由 Row、Column、Flex、Scroll、List 等构成的页面。若内容位于 Web、相机 Surface 或其他原生嵌入视图，应同时检查对应视图的尺寸更新。

## 原因与判断依据

| 排查位置 | 如何区分 |
|---|---|
| 头栏与主体的共同父容器 | 头栏已有高度，主体再设 `height('100%')`，两者总高可能超过页面；主体内部的权重不会扣除主体外面的头栏 |
| 滚动容器和内容层 | 滚动视口需要有界，内容应能超出视口；把内容层锁成一屏高，或让滚动视口随内容无限变高，都可能无法正确滚动 |
| 百分比与最小高度 | `minHeight` 只是下限。子项 `height('100%')` 的测量参照若落到列表视口，可能放大行高；不能断言所有最小高度都会撑满屏幕 |
| `constraintSize` 所在层 | 检查父约束、显式尺寸、最小尺寸及属性组合。已有有效父约束时，不写宽高也可能正常；不能给全树盲目补 `100%` |
| 浮层与正文 | Stack 中的底栏不占正文排版空间；正文未预留实际底栏高度才会被遮挡，使用 Stack 本身不是错误 |
| 短内容对齐 | 检查视口是否满高、外层是否居中，以及主轴对齐方向；不把所有居中内容一律改为顶部 |

## 解决方案

### 1. 先分配可用高度，再让主体滚动

头栏、主体和底部操作区放在同一个有界 Column 中。主体占剩余高度，只有内容层滚动。以下片段中的构建函数代表工程已有内容：

```ts
Column() {
  this.header()
  Scroll() {
    Column({ space: 12 }) {
      this.formFields()
    }.width('100%')
  }
  .width('100%')
  .layoutWeight(1)

  this.submitBar()
}
.width('100%')
.height('100%')
```

若 Scroll 外还有一层主体 Column，主体也要在其父容器中分配剩余空间，而不是重复声明整页高度。`layoutWeight` 适用于 Row、Column、Flex 的主轴分配，不是任意父容器通用属性；存在正权重时，不能再指望同一容器中的 `flexGrow`、`flexShrink` 按另一套规则分配空间。父主轴也必须有界。

### 2. 按内容类型处理溢出

- 长表单使用 Scroll；大量同质数据使用 List，避免整个长列表一次性堆进普通 Column。
- 列表行去掉无业务必要的 `height('100%')`，让文字和图片决定自然高度；保留必要的行最小高度。
- 窗口变短时，固定大空隙先收敛。需要首屏完整呈现的登录页可减少品牌区占位；普通长表单仍应可滚动，不能为塞进首屏删掉必需内容。
- 上下区用 `SpaceBetween` 时，只有内容总高小于容器才有剩余空隙可分配。内容过高后应让主体取得有界剩余高度并滚动，或按已确认方案收起非关键装饰；不能继续加间距或只改两端对齐。弹性 Blank 可吸收富余高度，但不能代替内容超高时的处理。
- 底栏不需要覆盖正文时改为兄弟节点；确需浮层时，正文末端预留浮层高度，并把系统避让空间与底栏自身高度分开计算。
- 短列表应顶部开始时，给滚动视口足够高度并修正父容器对齐；不要用大块空白占位把内容“推上去”。

## 注意事项与修复后检查

`clip(true)` 只能隐藏越界绘制，不能使按钮可达；`constraintSize` 也不能代替滚动。不要同时增加页面 padding、底栏占位和系统避让，造成重复留白。

分别检查短内容、长内容、横屏短窗口、键盘弹出和大字体：末项能滚到，底栏不盖正文，列表行没有异常增高，返回较大窗口后不残留旧高度。
