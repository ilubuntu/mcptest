# ArkUI Tabs 侧边导航不出现、切回底部失败与页签重叠

## Overview 总体概述

已确认大屏侧边、窄屏底部导航时，只改 Tabs 的 vertical 不够。位置、导航区宽高和排列模式若仍沿用旧值，会出现侧边条很矮、内容被压、图标文字挤在一起，或缩窄后仍残留侧栏。

## 问题现象与适用条件

- 预期侧边导航没有出现，或最大档位反而回到底部。
- 宽屏变窄后侧栏未恢复，正文仍留出旧侧栏宽度。
- 图标、名称或相邻页签重叠，底部条占用异常高度。

适用于已确认需要导航挪移的 Tabs 页面。保持底部导航也可以是正确设计，不能单凭设备是平板就判断原实现有错。

## 原因与判断依据

1. 断点没有更新，或消费端只读取了初始化值。对比实际容器尺寸、断点回调和组件使用的响应式状态。
2. 条件只覆盖 lg，遗漏 xl；或只在变宽时赋值，恢复窄屏时没有重设完整属性。
3. Tabs 框架区域已经转为纵向，tabBar 构建器仍保持原横向尺寸、固定大图标或 lpx 缩放。
4. 自定义侧栏通过 Stack/position 浮在正文之上，却没有为正文留空间。

## 解决方案

### 用同一条件配置整组属性

下面片段中 `useSideTabs` 由已确认的窗口或容器策略更新；页签构建和数据保持原有实现：

```ts
Tabs({
  barPosition: this.useSideTabs ? BarPosition.Start : BarPosition.End,
  index: this.selectedIndex
}) {
  this.tabPages()
}
.vertical(this.useSideTabs)
.barWidth(this.useSideTabs ? 96 : '100%')
.barHeight(this.useSideTabs ? '100%' : 56)
.barMode(this.useSideTabs ? BarMode.Scrollable : BarMode.Fixed)
.width('100%')
.height('100%')
.onChange((index: number) => {
  this.selectedIndex = index
})
```

96vp、56vp 只是示例，必须匹配项目的页签内容及实际导航区。底部系统避让另行按当前窗口处理；不能把避让高度当成侧栏每个页签的间距。

### 分别修导航区和页签内部

侧栏变纵向后，按图标、文字和触控区域设置单项最小空间；可设置适当上下间距，内容较多时允许滚动。单纯增加整个 barHeight 不会自动拉开自定义 tabBar 子项。

文字过长时提供合理换行、省略或更适合的导航呈现，不能删除可访问名称。图标与文字不应跟整窗宽度无限放大；核对 fp/vp 与项目使用的 lpx 缩放。

普通导航优先让 Tabs 自身参与布局，正文自然位于导航区之外。已有沉浸式媒体浮动导航时可以保留浮层，但要处理遮挡、触控和系统区域，不能把这一骨架复制给所有业务页。

### 保留选择与页面内容

方向和位置切换时沿用同一选中状态、业务数据与页面标识。若条件分支重建 TabContent，需确认输入、列表锚点和滚动进度能够恢复；不应为防重建统一禁止所有 if/else。

## 修复后检查

检查宽→窄→宽、最大档位、长页签名、大字体及页签数量变化。导航和正文均不越界，选中页不重置，所有页签可达，底部导航不会叠加侧栏的旧占位。
