# ArkUI 启动图标裁切、品牌文字缺失与自绘启动视频黑边

## Overview 总体概述

系统启动窗口先于业务页面出现，修改 ArkUI 首页不会改变它的资源展示。应先区分系统启动图标、增强启动页和应用自己绘制的欢迎图或视频，再选择配置或布局修法。完整画面、铺满窗口和不裁切，在素材与窗口比例不同的时候无法同时满足。

## 问题现象与适用条件

- 系统启动图标不完整，或整屏图片中的底部文字被切掉。
- 自绘欢迎页只占中央手机宽度，宽屏两侧空白。
- 启动视频保持比例后出现黑边，改 Cover 后关键内容被裁。
- 短窗口中 logo 占位过大，协议或进入按钮不可见。

## 原因与判断依据

1. 简易启动页通过 Ability 配置的 `startWindowIcon`、`startWindowBackground` 展示，图标不随窗口缩放；把单机型全屏设计放进图标资源不是可靠的布局方式。
2. 增强启动页由 `startWindow` 指向 profile，不是普通 ArkUI 组件；部分品牌资源在短窗口可能隐藏，不能放入唯一的关键操作或必读文字。
3. 自绘页面根容器仍固定为手机宽度，或图片区域过高。这属于应用页面约束，不是系统启动配置。
4. 视频的真实比例与窗口不同。Contain 可能产生留白，Cover 会裁切；原生视频表面还可能自行绘制黑色区域，挡住下层背景。

## 解决方案

### 系统启动窗口：按资源能力配置

简单 logo 保持简易配置，使用适当分辨率和透明边距，不在图标里拼整屏正文。256×256 是面向启动解码开销的建议尺寸，不是所有资源超过就必然裁切的系统判据。

API 19 起需要复杂插画或品牌区时，可在 Ability 配置 `startWindow: "$profile:start_window"`，对应 profile 示例：

```json
{
  "startWindowBackgroundColor": "$color:start_window_background",
  "startWindowAppIcon": "$media:start_icon",
  "startWindowBrandingImage": "$media:start_brand"
}
```

资源名称需真实存在，背景色是增强配置的重要条件。图标与插画的展示关系、品牌区空间及背景图 fit 应按所用配置核对；不要把关键协议或按钮设计为可能隐藏的品牌图片。

### 自绘欢迎页：保留操作空间

根容器跟随当前页面宽高，图片在有界区域内保持比例。短窗口可减少非关键品牌占位，或让内容滚动；不能把全部内容等比缩小到字和按钮都不可用。图片中的正文尽量改成独立 Text，便于换行、字号和无障碍处理。

### 视频：先选择留白、裁切或延伸背景

需要完整视频时保留真实比例，接受设计认可的背景留白；允许裁切时才使用 Cover。前景比例来自媒体宽高，不默认所有视频为 16:9。

若明确要求背景延续视频色彩，可使用静态背景或独立背景视频层。双视频方案中，背景填满容器、可做适度模糊；前景组件本身按比例设置边界，不能仍让全屏 surface 用 Contain 生成黑边覆盖背景。根据容器宽高和素材比例计算能完整放入的前景宽高，而不是固定只按高度扩展。

两个播放表面需要独立播放器或 controller；仅前景负责音频、交互及业务进度，背景静音，并与前景统一暂停、恢复和释放。不能共享同一个 surface，也不能为消除黑边无条件增加双播放器。

## 修复后检查

区分冷启动与应用内欢迎页检查。对窄屏、宽屏、短窗口和深浅色确认图标、品牌、正文及按钮；视频无重复声音、前景无误裁切，退出页面后资源释放。不能用热启动截图代替系统启动窗口验证。
