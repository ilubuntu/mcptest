# ArkUI Swiper 宽屏仍单项、轮播拉长与边缘留白

## Overview 总体概述

Swiper 在宽屏仍只显示一张时，可能把横幅拉得很大，也可能因外层固定宽度缩在中央。对于允许同时展示多项的轮播，适配重点是单项宽度和可见数量；对于一次只播放一段内容的引导页或播放器，保持单项则可能是正确设计。

## 问题现象与适用条件

- 折叠展开后轮播高度或单卡宽度过大，信息量没有增加。
- 多项显示时卡片贴在一起，或边缘空白被误当作项间距。
- 列数变化后当前索引、指示器和点击目标不一致。

适用于允许多项并排的 Banner、内容推荐和功能卡片轮播。不强制将全屏引导、单项放大预览改成多项。

## 原因与判断依据

1. 先检查 Swiper 所在内容区有没有被固定宽度或 maxWidth 限制；合理正文限宽不必取消，但误套的手机宽度应移除。
2. `displayCount` 没有变化时，整个宽度继续分给一项。仅更改内部 ImageFit 不会增加可见内容。
3. `itemSpace` 控制项目之间的空隙；`prevMargin`、`nextMargin` 控制视口首尾预留或露出，两者不能互相代替。
4. 子项还保留手算的手机宽度，或以单项索引假设更新曝光与指示器，造成布局与业务状态脱节。

## 解决方案

按容器宽度、最小卡片宽度和间距确定显示数量。采用整数 `displayCount` 均分时，让子项服从 Swiper 的分配；不要再逐项写固定宽度模拟多列。

```ts
Swiper() {
  ForEach(this.banners, (item: BannerData) => {
    this.bannerCard(item)
  }, (item: BannerData) => item.id)
}
.displayCount(this.visibleCount)
.itemSpace(this.visibleCount > 1 ? 12 : 0)
.prevMargin(0)
.nextMargin(0)
.indicator(this.visibleCount === 1)
.width('100%')
.height(this.carouselHeight)
```

示例中的数量、高度和数据类型由页面定义；12vp 只是示例间距。指示器在多项时隐藏是一种设计选择，若保留，需要确认其页数、分组切换和当前项含义一致。边缘需要露出下一张卡片时，另行设置首尾 margin，不能因此减少每项的实际可读宽度。

图片自身比例和裁切仍需单独处理：统一卡片框可以使用经确认的裁切，完整海报应保留全图。增加项目数后不要把高度也按整窗比例放大。

数量改变时核对当前索引是否仍有效，业务代码是否错误地把索引当成唯一可见项。循环、分组滑动及最后不足一组的处理取决于实际配置；不能简单用 `index + displayCount - 1` 当成永远合法的尾项编号。

## 注意事项与修复后检查

1/2/3 项只是常见示例，不是设备型号到列数的标准映射。若内容不足、最小卡片宽度不满足或业务规定单项，应保留对应策略。

检查一项数据、少于可见数量、多项数据、首尾循环及缩窄恢复；确认卡片能点、文字完整、曝光统计没有重复，选中状态和自动播放不因重排重置。
