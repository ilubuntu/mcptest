# ArkUI 圆角屏贴边文字和按钮被裁切

## Overview 总体概述

紧贴屏幕四角的按钮或文字可能落在物理圆角不可见区域，即使页面宽高正确也会被切掉。需要区分屏幕圆角、状态栏或挖孔避让、应用自己设置的 borderRadius/clip，避免通过缩窄整页制造新的大片留白。

## 问题现象与适用条件

- 页面中部正常，四角附近的图标、文字或点击区缺一块。
- 旋转、折展或切换显示屏后，原来的固定边距不再够用。
- 分屏或浮窗中也沿用圆角补偿，内容被无故向中间推。

适用于关键控件贴近物理显示边缘的 ArkUI 页面。处于窗口内部的局部卡片圆角，应先修卡片自身的裁剪和内边距，不调用显示屏接口解决。

## 原因与判断依据

1. 检查被裁控件的实际 bounds 和其祖先的 clip、borderRadius、遮罩；确认裁切来自应用还是显示边缘。
2. 对照当前窗口在显示屏上的位置。窗口没有贴到物理圆角时，不应套用屏幕四角的补偿。
3. 核对坐标和单位：圆角信息使用显示屏坐标及 px，而页面布局通常用窗口/组件局部坐标和 vp。只把半径除以密度，不转换窗口偏移，仍可能避让错误。
4. 系统状态栏、挖孔和导航区域有独立避让信息，不能认为圆角接口包含了全部安全区。

## 解决方案

API 23 起可查询当前显示屏的圆角信息。简化查询片段：

```ts
import { display } from '@kit.ArkUI'

try {
  const screen = display.getDefaultDisplaySync()
  const corners = screen.getRoundedCorner()
  // 每项包含 type、position 和 radius；坐标及半径单位为 px。
  // 映射到实际窗口/内容坐标后，再计算贴边控件的安全内缩。
} catch (error) {
  // 沿用页面已配置的安全边距，不中断页面显示。
}
```

示例仅展示默认显示屏查询；应用在其他显示屏上时，应先取得窗口对应显示屏，不能一直使用默认屏参数。接口可能返回空数组或不支持；运行时条件也要判断，不能只看编译 SDK。

对靠近圆角的关键控件局部内缩，或在该角附近提供足够内边距；背景、视频和装饰可以继续延伸。控件位于圆角弧中间高度时，可结合圆心、半径及控件矩形计算实际安全范围；简单固定边距只是保守设计方案，不是设备真实半径。

若目标版本低于 API 23 或无法取得几何信息，使用设计认可的安全边距降级，并保留已有系统避让。不要伪造机型参数，也不要把半径直接叠加到四条页面 padding，造成重复缩窄。

## 修复后检查

检查四角、横竖屏、折展后的显示屏变化，以及窗口不再贴边的状态。文字可读、点击区可用，页面内部没有多余缩进；不能只看组件树矩形在窗口内就断言物理圆角没有裁切。
