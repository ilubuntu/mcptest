# ArkUI 窄窗口按钮文字重叠、控件压扁与优先级显隐冲突

## Overview 总体概述

一行内容的总宽度超过容器后，必须决定谁收缩、谁换行、谁隐藏。只给所有元素同样的宽度，或者靠固定 margin 排列，容易让按钮压扁、文字重叠、边缘入口被裁掉。修法取决于内容能否省略，不能统一使用隐藏或缩字。

## 问题现象与适用条件

- 昵称、价格和操作按钮挤在一起，关键按钮只剩一部分。
- 九宫格在窄窗口仍硬排原列数，最右侧入口消失。
- 设置 `displayPriority` 后仍全部显示，或低优先级内容始终不再出现。
- 希望按钮等宽，实际只均分了空隙；宽屏两端留白异常。

适用于 Row、Column、Flex 中的普通界面元素；图库和同质列表的大规模增列应采用栅格或列表布局。

## 原因与判断依据

先测父主轴可用空间，再看子项尺寸、间距及收缩配置。主轴无界时，布局可能认为空间一直足够；`displayPriority` 放到间接后代也不等于控制父容器的直接子项。

此外检查是否有两套显隐：一边给子项设置优先级，另一边又按宽度 `slice` 数据或计算 `visibleCount`。后者提前移除了节点，布局引擎无法恢复它们。业务筛选、分页与这种重复的空间数量裁剪不是一回事。

## 解决方案

### 1. 单行保留操作，文字按需省略

```ts
Row({ space: 8 }) {
  Text(this.title)
    .maxLines(1)
    .textOverflow({ overflow: TextOverflow.Ellipsis })
    .flexShrink(1)

  Button('查看详情')
    .flexShrink(0)
}
.width('100%')
```

该例要求标题允许省略，按钮仍能放入最窄目标宽度。若按钮本身已超过可用宽度，应改成换行或纵向布局，而不是继续禁止所有子项收缩。

### 2. 所有信息都要保留时换行或降列

使用 `Flex({ wrap: FlexWrap.Wrap })` 承接多行标签，或降低 GridRow 每行列数。不要用 `displayPriority` 隐藏必须访问的入口；需要折叠时提供明确的“更多”入口。

### 3. 次要信息可隐藏时由优先级统一处理

`displayPriority` 适用于有界 Row/Column 及单行 Flex 的直接子项。优先值越大越先保留，同一优先组共同显隐；至少一个直接子项的值大于 1 才启用分级，不能只用 0/1。可用 3、2、1 等整数等级表达业务优先级；多个元素必须一起出现时，先包成一个直接子组件。

渲染完整候选集，让布局决定哪些组可见；不要同时按宽度手算数量。多行 Flex 不按同一机制处理，滚动方向无界的内容也不适合用优先级决定空间取舍。

顺序流程条与价值分组不同：若必须保留连续前缀，按业务顺序设置逐项递减等级，并让连接符随相邻节点隐藏，避免只剩孤立箭头。

### 4. 区分间距均分与宽度均分

- 间距均分：Row/Column 在有界主轴使用 `.justifyContent(FlexAlign.SpaceEvenly)`；Flex 使用构造选项 `Flex({ justifyContent: FlexAlign.SpaceEvenly })`。
- 子项等宽：在 Row/Column/Flex 中使用一致 `layoutWeight`，或采用 Flex 的 `flexBasis`、`flexGrow` 和收缩方案。两套方案不要混用：容器存在正权重时，子项不再按 flexGrow/flexShrink 分配。长文字仍需自己的换行或省略策略。

`SpaceEvenly` 不会把按钮本身变成等宽；`layoutWeight` 也不能在 Stack、Grid 或无界主轴中替代尺寸约束。

## 修复后检查

用最长文案、大字体、不同入口数量和最窄容器检查：关键动作可点，允许隐藏的内容能在变宽后恢复，同组不会残缺。上下区总高不足时采用同样的空间预算思路；`SpaceBetween` 不能自动解决内容总高超过视口的问题。
