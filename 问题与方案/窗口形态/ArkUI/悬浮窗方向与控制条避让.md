## Overview 总体概述

悬浮窗问题应先分清“窗口方向能力未开启”“当前窗口太小但布局未响应”与“系统控制条覆盖交互区”。前者需要声明和运行时调用配套，第二类修复布局约束，第三类只补实际缺少的顶部避让。不能因进入悬浮窗就把所有页面统一上推或锁定某个方向。

## 问题现象

视频或游戏在全屏正常，进入悬浮窗后仍呈竖向、画面和操作区显示不全；悬浮窗缩小后按钮被挤出。沉浸式页面进入小窗时，返回、关闭等顶部按钮被系统控制条盖住；离开小窗后顶部却多出一条空白，或退出视频页后其他页面仍保留横向多窗行为。

## 适用条件

适用于手机、折叠屏和平板支持的应用主窗口形态。横向多窗只用于页面确实支持横向布局的场景，不用于给普通竖向表单强行横屏。窗口 `FLOATING` 状态在平板不同模式下可能对应不同视觉形态，不能仅凭该枚举就认定控制条高度或窗口大小固定。普通应用内浮层、Popup 与系统悬浮窗口也不是同一对象。

## 原因与判断依据

- `preferMultiWindowOrientation` 与运行时 API 只做了一边，或调用的不是应用主窗口。
- 视频本身的适配比例、容器固定宽高有误。若同一窗口尺寸下不进入悬浮模式也能复现，说明主要是几何布局问题，不应继续增加方向 API。
- 页面隐藏状态栏或主动进入系统区域，却没有消费悬浮窗新增的顶部系统避让；普通已避让页面则可能被后加 padding 再次上推。
- 在 `windowStatusChange` 内立即查询 Rect、重新读避让区，把尚未更新的值用于界面，出现过渡跳动。
- 页面退出只恢复普通首选方向，没有关闭自身开启的横向多窗能力，窗口级策略继续影响后续页面。

## 解决方案

### 横向能力声明与运行时成对

目标 Ability 的 `module.json5` 声明 `"preferMultiWindowOrientation": "landscape_auto"`。在支持横向布局的页面生效期间，对其应用主窗口调用 `enableLandscapeMultiWindow()`；离开并不再需要该能力时调用 `disableLandscapeMultiWindow()`。两者自 API 12 起提供，需要核对目标系统能力，并处理 Promise 失败。

```ts
// win 为当前应用主窗口；在既有页面策略管理中配对调用。
await win.enableLandscapeMultiWindow();
// 页面退出横向多窗场景，且该能力由本页接管时：
await win.disableLandscapeMultiWindow();
```

不要对所有业务页无条件启用。若同窗口已有其他页面或全局策略管理横向能力，应由既有管理者合并需求，避免一个页面退出时关闭另一个页面仍需要的能力。页面可见性、导航离开与销毁并不总是同一时刻，应选取真正覆盖该能力生效期的生命周期。

横向多窗不替代播放器的等比缩放，也不保证小窗口内容都能容纳。宽高仍来自当前窗口或容器，图片视频按业务选择完整显示或裁切；操作区在短窗口下应有紧凑布局或可滚动路径。

### 控制条避让使用已有系统区域状态

先确认原页面是否已经避让且按钮可点。若已有安全区或父容器完整预留，不添加第二份。只有沉浸式页面确实被遮挡时，才把 `FLOATING` 条件与系统顶部区域结合，形成该页面所需的额外避让。

可在现有窗口状态持有者内使用以下组合。初始化在窗口就绪后读取一次；变化分别消费状态与避让区事件，不在状态回调里抢读：

```ts
let status = win.getWindowStatus();
let systemTopPx = win.getWindowAvoidArea(
  window.AvoidAreaType.TYPE_SYSTEM).topRect.height;

const publish = (): void => {
  AppStorage.setOrCreate('floatingTopPx',
    status === window.WindowStatusType.FLOATING ? systemTopPx : 0);
};
const onStatus = (next: window.WindowStatusType): void => {
  status = next;
  publish();
};
const onAvoid = (event: window.AvoidAreaOptions): void => {
  if (event.type === window.AvoidAreaType.TYPE_SYSTEM) {
    systemTopPx = event.area.topRect.height;
    publish();
  }
};
win.on('windowStatusChange', onStatus);
win.on('avoidAreaChange', onAvoid);
publish();
```

`getWindowStatus()` 需要 API 12 及以上。代码中的 `floatingTopPx` 表示该沉浸场景的顶部候选值，不应在所有页面直接叠加：消费方应与已经承担同一区域的安全区或 padding 去重。px 可用长度字符串绑定，或用当前窗口 UIContext 换为 vp；两条路径不要混用。离开 FLOATING 时归零的是这份“形态额外量”，不是清空页面仍需要的状态栏避让。

共享工具类已有 `windowStatusChange` 和 `avoidAreaChange` 时直接消费其状态，不另建全局监听。新增监听要保存引用，所有者结束时按引用 `off`；窗口已销毁的注销操作捕获异常并清除本地引用。需要切换完成后的准确 Rect 时，可在 API 20 及以上使用 `windowStatusDidChange`，但它仍不能替代专用避让区事件。

## 修复后检查

- 横屏视频进入悬浮窗后方向与操作区匹配，画面比例正确，缩小后仍可完成关键操作。
- 顶部控制条下方返回、关闭按钮实际可点击，不仅在截图里可见。
- 全屏、分屏、悬浮往返后没有重复顶部空白，也没有把正常状态栏间距清零。
- 离开目标页面、重复进入或快速切换后，横向多窗策略和监听均无残留，不影响普通竖向页面。
