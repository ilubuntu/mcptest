## Overview 总体概述

应用内分屏由不同 UIAbility 的独立窗口组成，不等于一个页面里的左右两栏。首次启动失败应检查声明和启动选项；首次正常、再次打开不更新，则重点检查实例复用时是否通过 `onNewWant` 更新页面正在使用的数据源。这两种问题不能只靠修改布局解决。

## 问题现象

点击“对照查看”后目标页全屏打开；两个窗口显示相同页面；首次传入的详情正常，但再次选择另一条记录仍显示旧内容；日志显示启动调用成功，目标页面却没有刷新。还有入口只按设备类型显示，导致窄窗口操作区被额外按钮挤压。

## 适用条件

仅在产品需要两个窗口独立并行操作时采用。`StartOptions.windowMode` 的主、副分屏启动能力自 API 12 起用于同应用内跳转，生效范围为支持该能力的折叠屏和平板；不能据此承诺直板手机也能用同一调用主动启动应用内分屏。设备与系统不支持时应保留正常单窗口路径。

普通详情页的 `Navigation` 分栏、平行视界及应用内分屏是不同方案，不应因为屏幕宽就默认新增第二个 Ability。分屏后几何空间不足仍由当前窗口的响应式布局解决。

## 原因与判断依据

1. 目标 Ability 未声明 `supportWindowMode` 中的 `"split"`，或错误写成 `"splitScreen"`。
2. `startAbility` 没有传入包含 `windowMode` 的 `StartOptions`；在 Want.parameters 中放一个同名业务字段不能替代启动选项。
3. singleton 目标实例已经存在，系统调用 `onNewWant`，而参数处理只写在 `onCreate`。
4. Ability 更新了某个新建 LocalStorage，页面却绑定旧实例；或页面没有使用传给 `loadContent` 的共享存储。
5. 两个 Ability 加载同一路径、复用同一全局详情键，导致内容相同或互相覆盖。检查各窗口的数据归属，不应先怀疑分屏比例。

## 解决方案

### 声明与启动选项配套

为参与的 UIAbility 配置实际支持的窗口模式。目标若采用 singleton 复用，还应声明 `launchType: "singleton"`。配置片段中的字段位于各自 `abilities` 条目，页面和 Ability 入口路径仍需分别配置：

```json5
{
  "launchType": "singleton",
  "supportWindowMode": ["fullscreen", "split"]
}
```

发起端的调用使用 `AbilityConstant.WindowMode`，不要使用不存在的 `WINDOW_MODE_FLOATING`：

```ts
import { AbilityConstant, StartOptions, Want } from '@kit.AbilityKit';

const want: Want = {
  bundleName: 'com.example.app',
  abilityName: 'DetailAbility',
  parameters: { itemId: selectedItemId }
};
const options: StartOptions = {
  windowMode: AbilityConstant.WindowMode.WINDOW_MODE_SPLIT_SECONDARY
};
await context.startAbility(want, options);
```

其中 `context` 为当前 UIAbilityContext，包名、Ability 名和业务参数须使用实际声明。调用处应处理启动失败并保留原页，不以无异常等同于布局已按预期生效。主屏入口需要选择主分屏时使用 `WINDOW_MODE_SPLIT_PRIMARY`。比例偏好 `splitRatio` 是 API 26 起的能力，不能把它作为旧系统分屏生效的必要参数。

### 首次与复用写入同一存储

以下为目标 Ability 内的核心片段，导入 `UIAbility`、`Want`、`AbilityConstant` 与 `window` 后使用：

```ts
private detailStorage: LocalStorage = new LocalStorage({ itemId: '' });

private applyWant(want: Want): void {
  const id = want.parameters?.itemId;
  if (typeof id === 'string') {
    this.detailStorage.setOrCreate('itemId', id);
  }
}

onCreate(want: Want, launchParam: AbilityConstant.LaunchParam): void {
  this.applyWant(want);
}

onNewWant(want: Want, launchParam: AbilityConstant.LaunchParam): void {
  this.applyWant(want);
}

onWindowStageCreate(stage: window.WindowStage): void {
  stage.loadContent('pages/Detail', this.detailStorage, (error) => {
    if (error.code) { return; }
  });
}
```

页面使用 `@Entry({ useSharedStorage: true })`，以 `@LocalStorageLink('itemId')` 绑定同一个键。收到新 ID 后触发对应数据加载；异步请求应防止旧响应覆盖新选择。不要在 `onNewWant` 每次重新创建 LocalStorage 或整页 `loadContent`，以免现有页面失去绑定或业务状态被清空。

### 保持入口和页面语义

宽窗口专用入口按当前窗口实测宽度与业务可用条件显示，分屏已激活时按产品交互保留。若既有设计采用 600vp 门槛，可保留这一策略，但它不是系统规定的通用分屏阈值；不应用“平板”标签或固定设备尺寸代替判断，也不应在窄窗口擅自新增入口。

目标页出现顶部空白时，再检查是否同时显示外层 Navigation 标题栏与 NavDestination 标题栏；只有确认重复时才隐藏多余的一层，不统一删除正常导航。

## 修复后检查

- 冷启动与目标窗口已存在两种情况下，均打开正确目标并显示当前参数。
- 连续选择不同记录，两窗口数据不串改，旧网络响应不会覆盖新内容。
- 不支持能力或启动失败时仍可单窗口使用，窄窗口入口与原布局保持一致。
- 分屏缩窄后内容可滚达，关闭一侧不错误清空另一侧业务状态。
