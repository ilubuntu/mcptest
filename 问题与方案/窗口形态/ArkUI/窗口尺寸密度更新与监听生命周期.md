## Overview 总体概述

页面应随当前窗口变化，而不是随设备物理屏幕尺寸变化。窗口宽高、显示密度、窗口形态和系统避让区是不同状态源，各自有专用通知。混在一个回调里全部重查，容易把旧值写回界面；只监听一种变化，则可能遗漏 DPI 更新或留下旧断点。

## 问题现象

旋转后右侧或底部残留空白；退出平板自由窗口后字体、卡片和断点没有恢复；拖动窗口大小时页面仍按全屏排版；页面反复进入后一次变化触发多次响应。严重时窗口已销毁，旧回调仍更新状态或注销监听时抛异常。

## 适用条件

适用于手机、折叠屏和平板的 ArkUI 窗口及入口组件。页面只需要局部容器大小时，可以直接消费容器的 `onSizeChange`，不必建立窗口管理器。已有共享尺寸或断点基础设施时优先修复它，不能每页再挂一组全局窗口监听。本文不涉及 2in1/PC 的适配策略。

## 原因与判断依据

- `display.on('change')` 通知的是显示变化，回调参数不是窗口宽高。随后立即查询显示属性还可能未刷新，更不能代表分屏后的可用窗口。
- 只监听 `windowSizeChange`，而系统显示大小调整改变了密度，物理宽高未变，因此没有触发尺寸回调。
- 在尺寸回调里重新读取尚未更新的 DPI，导致 px→vp 换算仍使用旧值；固定阈值比较随之错误。
- `windowStatusChange` 到达时窗口 Rect 可能尚未更新。若随后才出现尺寸事件，不能用第一帧 Rect 当最终结果。
- 匿名注册后用另一个函数注销，或使用不带回调的 `off()` 移除同事件全部监听；也可能业务页每次出现都重复注册而没有释放。

## 解决方案

### 按数据职责订阅

精确几何尺寸使用 `windowSizeChange` 的 `Size` 参数，不重新查询物理屏幕尺寸。需要系统宽度断点时，API 13 及以上可用当前 `UIContext.getWindowWidthBreakpoint()`，不要复制系统阈值自行还原；旧版本继续使用工程已验证的窗口或容器响应式方案。

涉及 vp 高度、间距或比例计算时，同时处理密度变化。`systemDensityChange` 自 API 15 起提供新密度，受 `SystemCapability.Window.SessionManager` 支持约束；优先使用该回调密度更新换算，不能立刻再查旧 DPI 覆盖它。自定义 px/vp 计算应维护当前窗口原始尺寸与最新密度，密度变化时即使没有尺寸事件也重算。页面自身已用 vp 和响应式约束表达的属性，不必全部改成手工计算。

以下片段演示数据来源分工，放在已有窗口所有者内；状态消费方按这两个来源统一刷新布局：

```ts
const onSize = (size: window.Size): void => {
  AppStorage.setOrCreate('windowWidthPx', size.width);
  AppStorage.setOrCreate('windowHeightPx', size.height);
};
const onDensity = (density: number): void => {
  AppStorage.setOrCreate('windowDensity', density);
};

win.on('windowSizeChange', onSize);
// 已确认 API 版本与设备能力后注册：
win.on('systemDensityChange', onDensity);
```

初始化时在 `loadContent` 成功、UIContext 就绪后读取一次当前窗口尺寸及密度，随后以事件更新。对于只需知道形态的分支使用 `windowStatusChange`；需要“状态切换且 Rect 已更新”时，API 20 及以上可选 `windowStatusDidChange`，低版本让尺寸交给 `windowSizeChange`。避让区仍由 `avoidAreaChange.area` 驱动，不因状态或尺寸变化就主动抢读。

### 监听与窗口所有权闭环

把订阅归属于实际窗口或入口，而不是每个业务组件；注册应幂等，只对当前持有的窗口生效。保存上述回调引用，销毁时分别调用 `off('windowSizeChange', onSize)` 与 `off('systemDensityChange', onDensity)`，只注销成功注册的事件。容器局部监听则随组件自然释放。

注销时窗口原生对象可能已经销毁，应对窗口操作捕获异常；即使注销失败也要清除本地引用、定时器和订阅标志，防止下一次复用旧对象。异步获取窗口和防抖回调还需检查所有者是否仍有效。业务输入、选中项和滚动状态不应因为尺寸更新而重新创建或清空。

### 小窗口仍不可用时检查尺寸下限

分屏或小窗口下的图片截断、文字挤压，首先复用窄窗口布局和滚动分支，不另写一套“分屏布局”。对支持自由窗口的平板，若用户能拖到超出业务最小可用范围，可在 Ability 的 `module.json5` 配置 `minWindowWidth`、`minWindowHeight`，或使用 `setWindowLimits()` 动态限制；限制不能替代范围内的响应式适配。

静态配置按 vp 表达；运行时 `WindowLimits` 默认是 px，API 22 起可通过 `pixelUnit` 明确选择 vp。不要把两者裸数值直接复用。运行时结果还受系统限制，需以接口返回的最终范围为准，不能假设所有声明会原样生效。下限应来自当前页面最窄可用布局，不照抄任意示例宽高。

## 修复后检查

- 全屏、分屏、悬浮和自由窗口往返时，尺寸、密度、断点分别更新，无底部或右侧旧留白。
- 调整系统显示大小，即使物理窗口大小未变，vp 计算仍正确。
- 拖到最窄允许窗口和断点临界位置，内容可滚达，关键控件未裁切。
- 重复进入退出、快速切换和销毁窗口，没有回调倍增、旧状态回写或异常崩溃。
