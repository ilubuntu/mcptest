## Overview 总体概述

`.customKeyboard(builder)` 的键盘宿主默认采用全宽，根组件主要控制面板高度，内部内容仍受 builder 的布局约束影响。右侧留白、底部留白和整体过高是三类不同问题：分别检查内容宽度、剩余高度分配和面板总高。启用 `supportAvoidance` 解决的是输入区域与键盘的避让关系，不会自动修复 builder 内写死的宽高。

## 问题现象

手机窄窗口中键盘看似正常，折叠展开后全部按键靠左，右侧出现大片空白；或标题和按键之间正常，按键下方却多出空隙。另一些页面在横屏、分屏时键盘仍沿用竖屏高度，挤走输入区和完成按钮，收起后布局恢复。

## 适用条件

适用于应用通过 TextInput 等组件挂载的自定义数字、安全或业务键盘，不用于系统输入法面板。先确认面板是否设计为全宽、分离式或紧凑型。已经明确的居中限宽、分离式键盘可以保留；不能把所有宽屏留白都判为错误，也不能默认所有键盘都应占窗口一半高度。

## 原因与判断依据

1. builder 根组件已经全宽，但内部标题栏或 Grid 仍是某个手机宽度。窄窗口中固定内容被裁或恰好填满，宽窗口才暴露右侧空白；左对齐会使空白集中到一边。
2. 根 Column 高度大于“标题 + 固定按键区”的总高，而按键区没有参与剩余空间分配。检查根节点、标题和 Grid 的实测高度，不能通过改总宽度解决底部空隙。
3. 根高度固定，或只在 `aboutToAppear` 读取一次屏高。停留期间折展、旋转、分屏后没有重新计算，面板继续使用旧值。
4. 用物理屏幕高度设计分屏内面板，或将 px 当 vp。即使比例计算正确，也可能相对当前窗口过高。

## 解决方案

### 宽度、内部填充和总高分别修复

产品要求全宽键盘时，根组件、标题和按键区域均使用父容器可用宽度，清除设备宽度常量；Grid 列使用均分或自适应规则。删除无意义的左对齐并不能替代改掉内部固定宽度。若按键本来要求限宽，则让按键组在面板内对称居中，按键间距和触达性仍需单独确认。

希望按键填满面板时，保留标题的必要高度，按键区用 `layoutWeight(1)` 分配余量。先算清“根总高是否包含底部导航避让”，同一份底部间距只处理一次。若空隙属于设计留白或安全区，不能通过无限拉高按键把它消除。

```ts
@Builder
numberKeyboard() {
  Column() {
    Row() {
      Text('安全键盘')
      Blank()
      Button('完成').onClick(() => {
        this.getUIContext().getFocusController().clearFocus();
      })
    }
    .width('100%')
    .height(44)

    Grid() {
      // 放入业务按键 GridItem，保留既有输入和删除逻辑。
    }
    .columnsTemplate('1fr 1fr 1fr')
    .width('100%')
    .layoutWeight(1)
  }
  .width('100%')
  .height(this.keyboardHeightVp)
}
```

这里的 `keyboardHeightVp` 是应用已有尺寸状态计算出的面板总高，不是系统键盘高度。总高可按当前可用窗口高度取产品比例，并结合标题、按键最小可用高度与上方输入区所需空间作上下限约束；比例和限值是设计参数，不是系统标准。短窗口无法同时容纳时应减少非关键装饰或采用紧凑布局，不能让键盘超出窗口。

全屏且设计明确按屏高计算时，也可读取屏高后通过当前 UIContext 转为 vp；但这一选择不能直接沿用到分屏和悬浮窗口。窗口内面板优先消费当前窗口或宿主容器的尺寸。折展、旋转和窗口缩放后由已有 `windowSizeChange` 或容器尺寸状态重算，密度变化时同步换算；不在 display 回调里立即取可能尚未刷新的屏幕属性。

挂载需要联动避让时使用 `.customKeyboard(this.numberKeyboard(), { supportAvoidance: true })`，并核对目标 API 支持。面板尺寸正确后仍被输入框覆盖，才继续检查避让配置，不能先把页面统一改为 RESIZE。

## 修复后检查

- 窄窗口、展开宽窗口及横屏短窗口下，按键没有裁切，左右留白符合设计而非偶然残留。
- 标题、按键和导航避让区总高闭合，没有多算一次底部安全区。
- 键盘显示期间缩放、折展后尺寸及时更新，不需要退出重进。
- 输入、删除、完成和收起仍正常；按键足够易触达，上方输入内容和光标可见。
