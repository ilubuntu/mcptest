## Overview 总体概述

键盘遮挡通常由可用高度减少后仍保留固定约束引起。修复需要同时考虑避让模式、内容伸缩、滚动可达和浮层独立布局。`UIContext.setKeyboardAvoidMode()` 控制页面布局，不等于弹窗配置；修改页面模式不能保证 `CustomDialog`、半模态和其他弹出组件自动采用同一行为。

## 问题现象

键盘弹起后输入框、协议或提交按钮消失；页面上移后标题进入状态栏；弹窗顶部越界、正文被裁或底部按钮被键盘盖住。短窗口聊天页还可能出现引用预览截断、输入框被压扁，横屏下找不到收起键盘入口。键盘收起后正常，是可用高度和避让链路问题的重要线索。

## 适用条件

适用于原生 ArkUI 表单、评论、聊天及含输入控件的弹出层。先区分系统键盘与 `.customKeyboard()` 自定义面板，也要区分底部固定键盘与浮动键盘。不能把某次读取的键盘高度当作所有输入法、所有窗口的通用高度。页面当前已经合理使用 OFFSET 时，不应仅因存在输入框就改成 RESIZE。

## 原因与判断依据

- 默认 OFFSET 主要通过上移避让；底部布局要求保留顶部标题和压缩中间内容时，它可能不符合页面预期。
- RESIZE 调整页面可布局高度，但固定 vp/px 高度的内容不会自行缩小。检查中间内容是否使用百分比或 `layoutWeight`，以及超出部分能否滚动。
- `RelativeContainer` 中锚定在旧容器边缘的固定块、固定高度编辑区及不可滚动协议区，会使避让后仍无处容纳内容；不是所有 `RelativeContainer` 都必须替换，而是要消除冲突约束。
- 主页面的 padding 不影响作为兄弟节点叠加的自绘弹层；真正的弹出组件还有自己的避让配置。
- 引用预览和输入框共用工具栏整体 `maxHeight` 时，短窗口中两者争抢空间。限高应优先落到可降级的预览区。

## 解决方案

### 页面模式与可伸缩结构配套

需要压缩内容区时，选择 `Column + List/Scroll`：标题在滚动区外，中间区域用 `layoutWeight(1)`，协议和提交按钮可放在滚动末尾；若底部栏必须常驻，也可置于滚动区外保持自然高度，但须确认剩余区域仍足够。`List` 可利用焦点输入项的滚动避让；使用 `Scroll` 时若焦点或末尾按钮仍不可见，再按布局完成时机滚动到目标，不能每次键盘变化都无条件跳到底。

API 11 及以上的页面模式包含 OFFSET、RESIZE；光标相关模式与 NONE 需要核对更高版本。不要使用不存在的 PAN。高输入框中的光标移动导致遮挡时，可评估 `OFFSET_WITH_CARET` 或 `RESIZE_WITH_CARET`，而不是只按输入框整体位置判断。

下面是页面生命周期片段，导入别名用于与弹窗同名枚举区分：

```ts
import { KeyboardAvoidMode as PageKeyboardAvoidMode } from '@kit.ArkUI';

private previousMode: PageKeyboardAvoidMode = PageKeyboardAvoidMode.OFFSET;

aboutToAppear(): void {
  const ui = this.getUIContext();
  this.previousMode = ui.getKeyboardAvoidMode();
  ui.setKeyboardAvoidMode(PageKeyboardAvoidMode.RESIZE);
}

aboutToDisappear(): void {
  this.getUIContext().setKeyboardAvoidMode(this.previousMode);
}
```

在 Ability 中配置时，应在 `loadContent` 成功回调、UIContent 就绪后调用；页面临时接管则按实际可见生命周期恢复原值，不能硬编码恢复为 OFFSET。多个页面共享窗口时优先沿用已有策略管理。RESIZE 下不要再以同一键盘高度缩一次根容器，也不要依赖扩展 KEYBOARD 安全区取消压缩。

### 弹窗单独处理

`CustomDialogControllerOptions.keyboardAvoidMode` 使用弹窗的 DEFAULT/NONE 语义，DEFAULT 负责自动避让，NONE 表示不避让；它不是页面枚举中的 RESIZE。项目同时使用两类枚举时应给页面导入起别名，避免同名误用。对半模态等组件核对其自身支持的配置，不能将一个弹窗选项套给所有弹出组件。

弹窗内部仍应限制最大可用高度，让正文滚动，标题、关闭和确认按钮按重要性保留。若弹窗顶部与状态栏重叠，要核查安全区与上移后边界，不是继续增加键盘偏移。

若弹窗实际上是页面 `Stack` 中的自绘兄弟层，且未由系统完成避让，可仅在该层以当前有效键盘区域调整可用高度或底部 padding，再在剩余区域内定位。该手工路径与系统已执行的压缩、上移只能按实际缺口组合，不能直接相加。`TYPE_KEYBOARD` 面向固定态软键盘；浮动键盘需结合实际遮挡判断，不按“底部整条高度”推断。

### 短窗口与关闭入口

引用预览按剩余高度缩为少量行或单行摘要，限高加在预览区，不加到整个输入工具栏。输入框和发送按钮保留可操作高度。横屏或短窗口下提供明确的“完成/收起”入口；一般可通过当前 `FocusController.clearFocus()` 清除焦点，必要时按输入会话使用输入法控制器停止会话。不要把仅控制一个输入组件的 `stopEditing()` 当作所有输入场景的统一关闭方案。

## 修复后检查

- 依次聚焦首项、末项和多行输入框，光标可见，协议与提交按钮可滚达。
- 键盘弹出、收起和切换输入法后，没有双重抬高、底部残留空白或输入数据丢失。
- 独立检查弹窗正文、关闭和确认按钮，不能只验证背后的主页面。
- 横屏、分屏和折叠短窗口下引用可降级、输入框不被压扁；离开页面后其他页面模式不变。
