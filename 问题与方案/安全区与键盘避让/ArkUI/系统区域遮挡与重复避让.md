## Overview 总体概述

安全区适配的目标是让背景可以连续延伸，同时保证文字、按钮和输入控件可见、可点击。状态栏、挖孔、底部导航指示条和应用自己的底栏不是同一层约束，不能靠统一增加一圈固定 padding 处理。应先确认页面是否已经由系统或父容器避让，再补足实际重叠部分。

## 问题现象

- 初次进入页面标题、返回按钮被状态栏压住，或折叠、展开后再次重叠。
- 横屏后挖孔移动到左右侧，贴边按钮看得见但点不到。
- 底部按钮被导航条盖住；列表可以滚动，最后一项却始终藏在底栏后。
- 页面底部出现多余空白，标题栏上方露出另一种背景色；旋转后顶部先跳一下再恢复。
- 沉浸式页面的状态栏图标与背景同色，虽然未重叠也无法辨认。

## 适用条件

适用于手机、折叠屏和平板的原生 ArkUI 页面，尤其是开启窗口全屏布局、主动忽略布局安全区或使用浮层底栏的页面。普通非沉浸页面若已自动避让，不应再套用全屏页面的手工间距。自由窗口的装饰标题栏也不等同于普通状态栏，不能指望扩展安全区属性替代装饰栏配置。

## 原因与判断依据

1. 只在窗口创建时读取避让区，之后保存的值没有更新；若首次正常、折展后异常，应检查 `avoidAreaChange` 是否持续分发。
2. 用 `windowSizeChange` 或 `display.on('change')` 回调重新查询避让区。尺寸变化不代表系统栏已经完成更新，旧值覆盖新值会产生跳动。
3. 底部导航指示条没有独立读取，或用固定 margin 模拟其高度。应检查 `TYPE_NAVIGATION_INDICATOR`，不要假定 `TYPE_SYSTEM.bottomRect` 总能代表底部导航区，也不要把它恒为零写成跨版本前提。
4. padding 层级错误：灰色外容器承担顶部间距，白色标题栏没有延伸；或只上推整个 `Stack`，没有为滚动末尾预留空间。
5. 系统默认避让、父级 padding 和子级 padding 同时生效，造成重复留白。同一方向的状态栏与挖孔区域若重叠，应计算覆盖范围，不直接相加。

## 解决方案

### 先选择延伸范围

只要求背景铺满时，将背景节点与交互内容分离，按需要对背景使用 `expandSafeArea`，内容保持安全区约束。`SafeAreaEdge` 使用 `TOP`、`BOTTOM`、`START`、`END`，不要写成 `LEFT`、`RIGHT`。扩展属性不会替应用自动保证所有子按钮都安全，仍需检查按钮的实际位置。

需要单页改变布局安全区时，API 20 及以上可按边使用 `ignoreLayoutSafeArea`，配合 `LayoutPolicy.matchParent` 和该容器自身的避让间距；无需因此切换整个窗口的全屏状态。确实需要窗口级沉浸时才使用 `setWindowLayoutFullScreen(true)`，等待设置完成后初始化避让区；页面临时修改窗口策略时，离开应恢复进入前的状态。

### 初始化一次，变化使用专用事件

复用窗口现有的避让区分发机制。初始化读取当前区域；后续根据 `avoidAreaChange` 的 `type`、`area` 更新，不在尺寸或方向回调里抢读。下面片段放入已有窗口状态持有者，`win` 为当前窗口：

```ts
const onAvoidArea = (event: window.AvoidAreaOptions): void => {
  if (event.type === window.AvoidAreaType.TYPE_SYSTEM) {
    AppStorage.setOrCreate('systemTopPx', event.area.topRect.height);
  } else if (event.type === window.AvoidAreaType.TYPE_NAVIGATION_INDICATOR) {
    AppStorage.setOrCreate('navigationBottomPx', event.area.bottomRect.height);
  }
};
win.on('avoidAreaChange', onAvoidArea);
// 所有者结束时：win.off('avoidAreaChange', onAvoidArea)
```

避让区数值通常是 px。页面可绑定 `"24px"` 一类长度字符串，或通过当前 `UIContext.px2vp()` 转为数值 vp；不能混用两套单位，也不能重复拼接 `px`。回调保存并按同一引用注销，不要求每页新建管理器。

### 按实际层级落地

顶部间距放在具有目标背景色的标题栏外壳，内部固定高度的标题内容单独一层，避免 padding 挤压文字。底部操作栏的背景可延伸到导航条下方，但按钮应上移；列表或 `Scroll` 自身还要预留浮层遮挡的尾部空间。计算时区分业务栏高度、系统导航条高度和纯视觉间距；若业务栏总高已包含导航区，不再重复加一次。

必须铺满的游戏、图片浏览等页面，再按 `TYPE_CUTOUT` 的非空矩形处理四边。窗口坐标中的上、左边界分别为 `top + height`、`left + width`；右、下的内缩量分别为“窗口宽 − rightRect.left”“窗口高 − bottomRect.top”。先判断对应矩形非空，再计算并限制到合理范围；矩形、窗口宽高必须使用同一坐标系，不能拿物理屏幕宽度替代分屏窗口宽度。普通页面无需为此复制全套四边管理器。

沉浸式图标不可读时，通过 `setWindowSystemBarProperties` 的状态栏内容颜色等属性，使图标与当前背景保持对比；切换主题、页面背景或退出沉浸页时同步更新和恢复。

## 修复后检查

- 滚到底后最后一项完整可达，浮层底栏与导航条均不盖住内容。
- 横竖屏、折展、全屏与分屏往返后没有旧间距闪回，也没有累计空白。
- 横屏左右挖孔附近按钮可点击，标题背景连续，固定行高未被挤压。
- 浅色、深色背景下系统栏图标清晰；重复进入退出后没有重复监听或策略残留。
