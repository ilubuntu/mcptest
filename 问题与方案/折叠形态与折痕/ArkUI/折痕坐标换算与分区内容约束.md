## Overview 总体概述

折痕避让应先计算真实区域，再在区域内部安排内容。屏幕折痕矩形不能直接用作页面的 vp 坐标；折痕位置正确，也不等于按钮、正文和弹层能够装进下半屏。两类问题需要分开判断，不能通过不断增加空白来掩盖坐标错误或内容高度不足。

## 问题现象

关键文字或按钮落在折痕上；避让区偏上、偏下或留出过大的空白；旋转后分区位置反复跳变；进入悬停后只剩空白。区域边界看似正确时，还可能出现下半屏文字重叠、进度条被压扁、主按钮越界，或者底部弹层透明区域拦截遮罩点击。

## 适用条件

坐标示例用于 API 20+ 的自定义悬停布局：全屏主窗口、单条可用于上下分区的横向折痕，根容器没有 translate、scale、transform 等绘制变换。系统组件已负责分区时，不重复运行这套几何定位，但仍要处理分区内部的内容与安全区。

## 原因与判断依据

FoldCreaseRegion.creaseRects 的单位为 px，页面布局通常使用 vp。折痕属于屏幕，页面根容器属于窗口，窗口原点和根容器原点不一定都为零。漏减其中任一偏移，或在换算中混用单位，都会导致避让漂移。

另一个常见原因是旋转后继续使用旧屏幕矩形。应从主窗口的 displayId 找到对应 Display，读取 getLiveCreaseRegion；该方法从 API 20 起支持。旧的 getCurrentFoldCreaseRegion 有自己的坐标定义，不能原样替换实时接口，也不能简单交换缓存矩形的宽高。display.convertGlobalToRelativeCoordinate 处理的是屏幕之间的坐标转换，不能替代屏幕到窗口、窗口到根容器的换算。

## 解决方案

### 将实时折痕转换到当前根容器

取得主窗口 getWindowProperties() 的 displayId、windowRect，并缓存根容器 onAreaChange 的实际宽高与 globalPosition。下面为计算片段，rect 与 windowRect 先保持同一屏幕坐标系、同为 px；根位置和根高为 vp。

```typescript
const leftVp = uiContext.px2vp(rect.left - windowRect.left)
  - rootLeftInWindowVp;
const topVp = uiContext.px2vp(rect.top - windowRect.top)
  - rootTopInWindowVp;
const widthVp = uiContext.px2vp(rect.width);
const creaseHeightVp = uiContext.px2vp(rect.height);
const displayHeightVp = topVp;
const actionTopVp = topVp + creaseHeightVp;
const actionHeightVp = rootHeightVp - actionTopVp;
```

globalPosition 是根容器在窗口/页面中的位置，不是屏幕原点。使用当前窗口 UIContext.px2vp，避免跨窗口密度不同仍沿用旧换算。根容器有绘制变换时，必须先明确变换后的坐标关系，不能继续套用本公式。

激活分区前检查：折痕 region.displayId 与当前 Display 匹配；矩形各值有限、宽高大于零；换算后横向覆盖根容器；topVp 大于零，actionTopVp 小于根容器高度。可以为像素量化留极小比较容差，但容差不是设计间距。读取失败、多折痕、方向不符或上下区高度不合法时保留普通布局，等下一次尺寸、显示或根区域变化再算，不把异常矩形强行钳成固定厚度。

### 在分区内部解决内容溢出

真实折痕的上下边界决定两个区域的位置；保护距离放在区域内的 padding 中。先明确设计距离从折痕中线还是边界起算，避免与系统避让或已有 padding 重复。

操作区优先为主按钮、进度条及底部避让预留空间，次要内容只使用剩余高度：

```typescript
Column() {
  Scroll() { this.secondaryInformation() }
    .width('100%').layoutWeight(1)
  this.progressBar() // Builder 内的控件也需设置合理最小高度
  Button('主要操作').flexShrink(0)
}
.width('100%').height('100%')
.padding({ top: this.creaseGapVp, bottom: this.bottomInsetVp })
```

代码中的间距、主按钮与字号应使用页面设计资源；不要仅按整屏宽度放大所有控件。若不可压缩内容本身已经高于操作区，需缩减次要展示、折叠辅助信息或调整交互，而不是靠 flexShrink(0) 保证它“自动装下”。List、Scroll 的父容器必须拥有有界高度。

展示区图片、视频按本区域宽高约束并保持原比例。需要全图时用 Contain；允许裁剪时用 Cover 并确认焦点；Fill 会改变比例。若 SVG viewBox 或素材本身已裁掉文字，改适配模式不能恢复素材内容。

沉浸式页面应单独处理导航条避让 TYPE_NAVIGATION_INDICATOR，不假定 TYPE_SYSTEM.bottomRect 总能代表手势导航条。底部 inset 由已有安全区管理器提供，并只在负责避让的层应用一次。

### 限制区域内弹层，而非放大透明滚动层

下半屏的底部卡片高度取“设计上限与操作区实际可用高度”的较小值，卡片内部滚动；遮罩独立铺满操作区并响应关闭。不要让全区透明 Scroll 包住一个仅限宽的卡片，否则透明滚动层可能拦截遮罩点击。锚定菜单继续跟随触发控件，不统一改为底部卡片。

## 修复后检查

- 核对折痕、窗口和根容器的单位、原点、display 归属，旋转后不复用旧矩形。
- 暂时无折痕或几何不合法时仍能操作普通页面，没有负高度或空白页。
- 大字号、长文案、短操作区下，主要操作可见，次要内容可滚动到末尾。
- 手势与三键导航、弹层打开关闭时没有重复底部留白，也没有透明层阻断点击。
