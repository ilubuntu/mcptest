## Overview 总体概述

悬停不是“窗口够宽”或“设备处于半折”这一个条件。系统组件是否进入悬停、自定义页面是否具备有效分区几何、页面是否需要主动改变方向，是三件不同的事。先确认页面使用 FolderStack、FoldSplitContainer 还是已有自定义布局，再修复各自缺失的条件，不能把一种实现的规则套给另一种实现。

## 问题现象

设备半折后仍显示普通页面；竖屏半折始终不转向；或者窗口和折痕尚未更新，页面就提前切成上下两块，出现重叠、闪动。另一类问题是普通态正常，一旦把 FolderStack 放进条件分支，悬停能力便消失。

## 适用条件

适用于原生 ArkUI 展示区与操作区的悬停适配。FolderStack 从 API 11 起支持，本文使用的 onHoverStatusChange 从 API 12 起支持，且仅适用于 Stage 模型。其悬停能力针对组件支持的双折叠设备，不据此承诺三折、多折轴设备也有相同行为。自定义几何方案以下以 API 20+、全屏主窗口、单条横向折痕的上下分区为边界。

## 原因与判断依据

FolderStack 的 upperItems 必须对应要移到上区的直接子组件 ID；数组为空时就是普通 Stack。容器及父布局未撑满页面，或者父节点为 if/else 条件渲染节点，都会破坏悬停接入前提。判断是否已经进入悬停，应消费回调中的 isHoverMode，不用宽度阈值或 HALF_FOLDED 覆盖组件结果。

自定义实现则要分别取得折叠状态、当前窗口状态和根容器几何。展开与半折可能具有相同窗口尺寸，宽度不能识别悬停。折叠事件也不保证晚于窗口更新；只在 foldStatusChange 中计算一次，容易读到旧尺寸。FOLD_STATUS_UNKNOWN 表示状态未知，不能单独当作“设备不支持折叠”的能力结论；能力与状态应分开判断。

## 解决方案

### 系统组件：保持稳定容器，按组件结果调整内容

下面是组件内部结构片段，displayContent、actionContent 为页面已有 Builder，hovering 为页面状态；接入时保留原有业务节点及 ID。

```typescript
FolderStack({ upperItems: ['display-region'] }) {
  Stack() { this.displayContent(this.hovering) }
    .id('display-region')
    .width('100%').height('100%')
  Stack({ alignContent: Alignment.Bottom }) {
    this.actionContent(this.hovering)
  }.width('100%').height('100%')
}
.width('100%').height('100%')
.autoHalfFold(true)
.onHoverStatusChange((event: HoverEventParam) => {
  this.hovering = event.isHoverMode;
})
```

外层父布局也须撑满页面，不以 if/else 包裹 FolderStack。autoHalfFold 的默认值为 true，它控制系统自动旋转关闭时，半折布局是否补充自动旋转，不是悬停总开关。若已有方向管理器接管这部分行为，应明确协调该属性，不能让系统组件和多个业务回调相互写方向。

普通态与悬停态都适合固定二分栏、三分栏时，可选 API 12+ 的 FoldSplitContainer，通过 primary、secondary 等 Builder 以及各形态布局选项表达区域。其悬停规则包含窗口宽度大于 600vp、横屏半折；小于等于 600vp 时默认二分栏。这是该组件的规则，不是通用悬停门槛。区域比例也不是百分数字面量。

### 自定义布局：先请求所需方向，再等待有效几何

保留已有窗口与方向服务，将 foldStatusChange、windowSizeChange、相关显示变化及根容器 onAreaChange 汇入同一个刷新入口。折叠事件只更新形态信号；普通页面的列数、密度继续按实际窗口或容器宽高决策。

若产品明确要求半折时主动转向，检测到半折且窗口满足方案条件后就请求选定的 window.Orientation。不要写成“半折且已经横屏才请求横屏”，否则竖屏永远没有机会转向。方向请求 Promise 完成也不表示根容器已经重新布局。

随后用窗口当前 display 的实时折痕和根容器最新尺寸重算：折痕在根容器内横向覆盖，且上下可用高度都大于零，才激活上下布局。几何未就绪时保持普通布局并等待后续事件，不以固定延时、屏幕中线或旧矩形补出假分区。多折痕、竖向分区和非全屏场景需明确另行设计。无需主动转向的页面沿用原窗口策略，不强制所有半折页面横屏。

## 注意事项

系统分区和自定义折痕分区二选一，不能叠加两次避让。保持两个区域容器存在，也不代表其中两套条件分支里的 List、输入框或 Video 没有重建；有状态内容还需按《ArkUI 折展连续性与异步任务回收》的方法处理。展示区和操作区内部都应受各自可用高度约束，不能继续使用整屏绝对坐标。

## 相关方案

采用自定义分区且需要计算折痕位置时，读《ArkUI 折痕坐标换算与分区内容约束》；若分区切换导致输入、路由或播放状态丢失，读《ArkUI 折展连续性与异步任务回收》。系统容器已负责分区时不重复套用自定义几何方案。

## 修复后检查

- 从竖屏、横屏分别进入半折，核对分区是否只在满足所选方案条件时出现。
- 分别打开、关闭系统自动旋转，检查 autoHalfFold 与页面方向策略是否一致。
- 半折、展开、内外屏切换后确认区域会重新计算；无有效折痕时普通布局仍可用。
- 反复进入页面后没有重复监听，离场后不再收到影响当前窗口的旧回调。
