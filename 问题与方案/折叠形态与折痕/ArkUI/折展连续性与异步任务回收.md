## Overview 总体概述

折叠开合应该改变页面的可用空间，不应替用户重新开始业务流程。布局变化与业务状态分离后，路由、输入、阅读锚点和播放意图能够持续存在；确需重建组件时，再做有时机、有版本校验的恢复。折展事件和尺寸事件可能先后到达，不能靠一次固定延时保证全部连续性。

## 问题现象

展开后回到首页，表单清空，列表跳顶，暂停视频自行播放，播放进度回退；切到外屏后仍沿用内屏大尺寸，或展开后只占半屏。反复开合还可能出现双重闪动、方向反复切换，页面离开后旧任务仍改变当前页面。

## 适用条件

适用于原生 ArkUI 页面在内外屏切换、折展、悬停分区或旋转重排中的状态连续性。以下方案不负责进程被系统终止后的持久化恢复；如果实际发生 UIAbility 重新创建，需要结合应用既有状态恢复机制，不能用内存字段冒充跨进程存储。

## 原因与判断依据

先记录路由和组件生命周期，区分“同一实例仅改变尺寸”与“条件分支销毁后创建了新实例”。将同一个 List、Video、输入框分别写进两套 if/else，通常会得到两套独立状态。只保留外层 Builder 或复用一个 Scroller，并不能自动保证内部实例和滚动位置连续。

尺寸问题则核对数据入口：初始 windowRect 与 windowSizeChange 是否进入同一个断点更新方法，局部区域是否消费 onAreaChange 的真实约束。foldStatusChange 到达时窗口可能仍是旧尺寸；同时用它和窗口事件各算一次列数，容易先错排、后纠正，表现为连续闪两次。普通列数、内容密度不应直接由折叠枚举决定。

## 解决方案

### 保持状态所有者与业务节点稳定

路由栈、输入草稿、播放器控制器和列表控制器继续由当前页面或既有服务持有。优先改变同一节点的宽高、列数和位置，而不是为折叠态、展开态各写一套有状态组件。输入内容双向同步到稳定状态；弹层开关、选中项也不要仅存在于即将销毁的子节点中。无状态装饰可以条件渲染，但不要为了动效重建整个业务页面。

窗口管理层初始化时同步当前宽高，随后消费 windowSizeChange 回调参数；根容器用实际宽高决定局部布局。内外屏变化后更新断点与资源密度，紧凑布局依据内容、字号及触控要求，不依据单一机型的物理像素阈值。

### 用业务锚点恢复阅读位置

List 用 onScrollIndex 记录首个可见项，布局变化前冻结锚点，新布局完成后再由 scrollToIndex 恢复。内容可能增删或重新排序时，保存稳定条目 ID 并查找新索引，比保存旧索引可靠。需要精确阅读位置时再保存项内偏移，不能把旧像素偏移直接视为新布局下同一内容。

下面是恢复调度中的关键片段，afterNewLayout 为工程已有的布局完成调度，不是系统 API；没有该设施时可按目标 SDK 接入合适的帧后回调，并确认组件已就绪。

```typescript
const revision = ++this.restoreRevision;
const anchorId = this.firstVisibleItemId;
this.afterNewLayout(() => {
  if (!this.active || revision !== this.restoreRevision) { return; }
  const index = this.items.findIndex(item => item.id === anchorId);
  if (index >= 0) {
    this.scroller.scrollToIndex(index, false, ScrollAlign.START);
  }
});
```

恢复期间不要让新布局产生的过渡 onScrollIndex 覆盖待恢复锚点。用户主动滚动、换数据源或再次切换布局时，使上一轮恢复序号失效。WaterFlow 列数变化时可评估目标版本支持的 SLIDING_WINDOW 焦点保持能力，但仍需验证数据变更和实际滚动结果，不对所有滚动组件承诺自动保持。

### 媒体同时保存进度和播放意图

能保留原媒体节点时，不应每次折展都额外 seek。确需重建时，在业务状态中保存媒体 ID、进度、播放/暂停状态及恢复请求序号；新媒体 onPrepared 等就绪回调到达后，确认媒体 ID 和序号仍匹配，再恢复进度与播放意图。autoPlay 不得抢先覆盖原暂停状态。

恢复期间媒体自身产生的暂停或更新时间回调，应区分是用户操作还是程序恢复，避免把过渡事件写回快照。用户在等待期间切换视频、拖动进度或点击暂停，应使旧快照失效。定时器只能辅助重试或超时提示，不能代替媒体就绪信号；固定等待若干毫秒后无条件 start，会造成暂停态复播和旧任务串片。

### 将生命周期与异步副作用成对回收

监听回调保存在成员中，on/off 使用同一个引用；不使用另一个匿名函数尝试注销，也不裸 off 清掉其他页面的共享监听。按实际路由显示/隐藏与页签激活交接，不能假定隐藏就会触发 aboutToDisappear。

异步取得窗口、加载资源或准备媒体前记录会话序号，返回后检查页面仍激活且序号匹配，再注册或恢复。离场时更新序号、停止本页计时器并逐项注销监听，不能因一项注销失败跳过其余项。方向请求集中去重、串行执行；已发出的请求不能假定可取消，应等待后恢复本页覆盖前的策略。重新进入前完成上一轮方向交接，避免把临时横屏误存成初始策略。

## 修复后检查

- 在非首页、表单已输入、列表中部、媒体播放与暂停状态下分别反复开合，业务上下文不丢失。
- 内外屏切换与分屏缩放后，列数、宽高和紧凑密度使用新约束，没有先错排再恢复的双闪。
- 快速连续开合并立刻返回，旧阅读恢复、媒体回调和窗口请求不会覆盖新页面。
- 大数据页面旋转时不重复拉取或同步执行耗时初始化；确认优化前后不是通过清空页面掩盖卡顿。
