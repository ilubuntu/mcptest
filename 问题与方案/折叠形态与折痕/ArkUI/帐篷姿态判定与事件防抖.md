## Overview 总体概述

HarmonyOS 的 FoldStatus 没有通用 TENT 枚举。帐篷布局属于产品定义的姿态能力，必须先确定目标机型、使用哪一面屏、涉及哪条折轴，再组合信号判断。折叠角度、外屏显示或窗口横向中的任意一项，都不足以独立证明当前是帐篷。

## 问题现象

立起设备后没有进入专用布局；内屏悬停或桌面平放却进入帐篷；进入与退出反复抖动；加入防抖后方向切换永远不执行。冷启动已经摆成目标姿态时可能一直不触发，移动铰链后才恢复。

## 适用条件

适用于已有明确帐篷产品需求、能取得对应折叠与传感器信号的原生 ArkUI 页面。以下组合来自 Mate XT 的局部姿态经验，仅说明该场景如何排除误判，不是 Mate XT 所有双折轴组合态的完整模型，更不能推广为全部单折轴、双折轴设备的统一检测器。

对于单折轴设备，需要重新确认 FOLDED、MAIN 与目标姿态的对应关系；对于双折轴或更多折轴，必须明确角度数组的每个元素对应哪条轴、哪组折痕参与判定。无法确认映射时保留普通布局，不用“任一角度符合”冒充多折轴适配。

## 原因与判断依据

折叠角度窗口可能同时覆盖悬停姿态。仅判断角度加 MAIN，会把半折悬停误认成帐篷；只看窗口横向，也不能排除平放或普通横持。窗口旋转不改变机身固定坐标系中的重力轴，物理姿态应从传感器轴判断，不能用刚刚请求的窗口方向反过来证明姿态成立。

foldAngleChange 从 API 12 起提供角度变化事件，不能依赖一个不存在的同步角度读取过程。冷启动后铰链不动时，可能没有新角度事件；“暂未收到样本”与“已收到且不符合”必须分开。FoldStatus 的 UNKNOWN 也只是无法确定状态，不应视为目标设备能力不支持。

## 解决方案

### 按已验证的姿态组合做互斥判定

以该 Mate XT 局部场景为例，门槛是 FOLD_STATUS_FOLDED、FOLD_DISPLAY_MODE_MAIN、重力判断的物理横放，以及目标折痕在其原生坐标系中符合预期轴向。半折悬停必须排除，二者不能同时激活。下列为条件组合示意，布尔量由已校验的设备信号生成，不是可以直接跨设备复用的完整检测器。

```typescript
const folded = status === display.FoldStatus.FOLD_STATUS_FOLDED;
const outer = mode === display.FoldDisplayMode.FOLD_DISPLAY_MODE_MAIN;
const angleOk = anglesKnown
  ? relevantAxesMatchPolicy
  : allowStatusFallback && folded;
const candidate = gravityReady && folded && outer && angleOk
  && physicalLandscape && expectedNativeCreaseAxis;
```

重力首样本未到时不激活，订阅失败或样本失效时进入明确的降级状态。物理横放可结合重力在机身平面内的模长、横纵轴相对大小排除平放和竖持，但阈值受机型、轴定义及姿态范围影响，须配置化，不把某次角度范围、轴比或模长当作通用常量。原生折痕的轴向判断也只描述所选接口、所选设备的坐标约定，不能断言所有折痕矩形都天然横向。

冷启动的状态回退必须由产品确认：只跳过“尚无角度样本”这一项，不跳过外屏、重力、折轴等其他门槛。已经收到不合格角度时不能继续回退放行。重新启动订阅或显示形态切换后，应清除不属于当前会话的旧样本，避免上一次角度被当成当前证据。

### 使用不会被同向事件重置的防抖

重力回调会持续产生。若每次收到相同候选值都 clearTimeout 后重设，事件间隔短于防抖时长时，切换永远得不到执行。下面为状态类内部片段，candidate 为最新候选值，committed 为已提交值，两个延时为产品配置：

```typescript
private updateCandidate(next: boolean): void {
  this.candidate = next;
  if (next === this.committed) {
    if (this.timerId !== -1) { clearTimeout(this.timerId); }
    this.timerId = -1;
    return;
  }
  if (this.timerId !== -1) { return; } // 相同目标不重置期限
  const target = next;
  this.timerId = setTimeout(() => {
    this.timerId = -1;
    if (this.active && this.candidate === target) {
      this.committed = target;
      this.publishTentState(target);
    }
  }, next ? this.enterDelayMs : this.exitDelayMs);
}
```

候选值回到已提交状态时才取消挂起切换；离场清理计时器，并使旧会话回调失效。通常进入较短、退出较长可抑制边界抖动，具体时间仍需按业务校验。姿态检测只发布状态，方向请求由已有方向管理器串行执行，不在每个传感器回调里重复转向。

## 注意事项

sensor.on/off 使用同一回调引用，按实际选择的传感器核对系统能力、权限和订阅错误；不要把加速度传感器的权限要求无条件套给重力接口。页面隐藏但未销毁时也应停止不再需要的采样。可选的稳立检测有独立的设备与版本条件，不能把未支持或暂未返回等同于姿态不成立。

## 修复后检查

- 冷启动直接处于目标姿态，区分无角度样本与不合格样本，降级符合产品要求。
- 悬停、平放、竖持均不误入；多折轴分别验证各轴组合，不只验证一个角度。
- 持续同向传感器事件不会阻止防抖到期，反向姿态变化可撤销挂起切换。
- 快速进入退出页面后，没有遗留订阅、旧计时器或方向请求影响下一页。
