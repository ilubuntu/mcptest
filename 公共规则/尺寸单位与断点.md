# 尺寸单位与断点

适用范围：本知识库中的设备尺寸、预览基线及窗口／容器断点。
核验日期：2026-11-02。

本文说明参数如何记录和使用，不维护具体机型尺寸，也不规定各断点必须采用多少列或何种导航。

## 1. 尺寸与单位

| 信息 | 单位或形式 | 含义 |
|---|---|---|
| 屏幕对角线 | 英寸 | 硬件屏幕的对角线长度，不是应用可用面积 |
| 屏幕分辨率 | `px` | 机型规格中对应屏幕的像素尺寸 |
| 运行态窗口尺寸 | 保留来源单位 | 当前应用窗口的宽高；不能与屏幕分辨率混用 |
| 布局逻辑尺寸 | `vp` | HarmonyOS 布局使用的逻辑尺寸 |
| 字体尺寸 | `fp` | HarmonyOS 字体尺寸单位，应考虑字体缩放 |
| HTML 预览尺寸 | CSS `px` | 高保真画布及缩放后的浏览器展示尺寸，不是设备物理分辨率 |
| 高宽比 | `h / w` | 同一窗口或容器、同一单位下的高度除以宽度，无单位 |

宽高统一按“宽×高”记录，字段或表头中必须标明单位、方向及数据性质。方向变化后重新读取实际值，不能只替换方向名称。

`window.getWindowProperties().windowRect` 的宽高单位为 px。使用其他框架、布局回调或测试工具输出时，应核对其接口单位，不能因为字段叫 width/height 就默认是 vp。

## 2. 分辨率不能直接代表窗口

屏幕硬件分辨率、系统显示区域和应用窗口是不同对象。全屏、分屏、自由窗口、系统避让和应用容器约束都可能改变最终可用空间。

- 读取窗口数据时明确采集对象，不把整块屏幕尺寸写成应用内容区域尺寸。
- 安全区、键盘等占用还需结合工程实际布局方式处理，不能一律在窗口宽高上重复扣减。
- 分栏中的子页面应参考所在容器的实际空间，不能继续按整窗宽度选择内部布局。
- 字体缩放与显示缩放不是同一配置，验证时分别记录。

## 3. px、vp 与预览尺寸的使用

### px 与 vp

不能统一按 `/3`、`/2.5` 等常量将所有机型的 px 换成 vp。换算必须采用对应运行环境的有效密度及正确上下文，并注明依据。

优先使用工程对应的系统单位转换能力。自行计算时必须确认密度来源及单位；使用同一物理屏幕的硬件 PPI，不能替代应用有效显示密度。

若官方同时给出 px 与 vp，分别按官方原值收录，并保留向下取整等说明，不用重新换算的结果覆盖官方值。

### HTML 高保真

先按目标逻辑宽高构建画布，再以同一比例缩放宽和高。可约定“1vp 对应画布中的 1 CSS px”表达设计尺寸，但必须说明这是预览约定，不是设备物理像素换算。

设备边框、说明文字和预览缩放不应反过来改变目标逻辑画布尺寸。屏幕英寸也不能从预览图大小或 vp 数值直接推算。

## 4. 横向断点参考

以下为官方文档列出的窗口宽度参考区间。宽度必须大于 0，单位为 vp。

| 横向断点 | 窗口宽度 w |
|---|---|
| `xs` | `0 < w < 320` |
| `sm` | `320 ≤ w < 600` |
| `md` | `600 ≤ w < 840` |
| `lg` | `840 ≤ w < 1440` |
| `xl` | `w ≥ 1440` |

边界值属于右侧区间：600 为 md，840 为 lg，1440 为 xl。宽度为 0 或尚未取得有效尺寸时，应视为未初始化，不能当作正常 xs 窗口。

这些是参考阈值，不是每台设备永久不变的事实。官方说明个别设备可能存在产品化阈值调整；工程也可能有明确的自定义断点。

来源：[界面响应式布局](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-multi-device-responsive-layout)。

## 5. 纵向断点参考

本知识库中的纵向断点按高宽比 `r = h / w` 表示，不是按窗口高度的绝对 vp 值分类。

| 纵向断点 | 高宽比 r | 比例特征 |
|---|---|---|
| `sm` | `0 < r < 0.8` | 扁宽 |
| `md` | `0.8 ≤ r < 1.2` | 接近方形 |
| `lg` | `r ≥ 1.2` | 窄长 |

高宽比使用同一个窗口或容器的宽高，不能混合窗口宽度与内容区高度。宽高任一无效时不计算。

如果某框架或工程另设“短窗口高度小于某个值”的规则，应明确命名为可用高度阈值，不能与本表的纵向断点共用含义。

来源：[界面响应式布局](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-multi-device-responsive-layout)。

## 6. 窗口断点与容器断点

| 作用范围 | 用于什么 | 取值原则 |
|---|---|---|
| 窗口断点 | 页面整体布局、主导航、整页结构 | 当前应用窗口 |
| 容器断点 | 分栏内列表、局部卡片、嵌套区域 | 该组件实际获得的容器空间 |

ArkUI 中，支持的 SDK 可使用 `UIContext.getWindowWidthBreakpoint()`、`getWindowHeightBreakpoint()` 获取系统窗口断点，在窗口尺寸变化后更新。

局部布局可根据工程及 SDK 选择容器能力，例如 `ContainerReader`，或使用 `GridRow` 的组件尺寸参考方式。采用自定义断点时，明确参考对象与阈值来源，避免系统断点、项目断点及页面手写阈值相互矛盾。

`GridRow` 的断点配置需显式核对，不能因系统窗口断点支持 xl，就假定当前 GridRow 也使用了相同的全部阈值。组件能力、默认值及版本支持以对应 API 为准。

## 7. 动态更新与框架边界

- 窗口缩放、旋转、折展、分屏切换后，重新获取当前作用范围的尺寸与断点。
- 显示密度变化时核对逻辑尺寸和断点是否需要更新，不能继续使用初始化时的换算结果。
- UIContext 的系统窗口断点用于 ArkUI；H5、RN、Flutter 应使用对应框架的窗口或容器能力，不直接照搬 ArkUI API。
- H5 CSS px、RN 逻辑尺寸、Flutter logical pixels 与 HarmonyOS vp 不在缺少依据时直接等同，跨宿主比较需确认缩放与单位映射。
- 所有断点分支须覆盖任务涉及的范围，不能只处理 lg 而漏掉 xl。

## 8. 数据性质和优先使用场景

| 数据性质 | 可以用于 | 不能冒充 |
|---|---|---|
| 官方规格或官方开发参考值 | 设备知识、参考预览、规划覆盖范围 | 当前运行窗口 |
| 运行态实测 | 对应机型、系统、显示缩放和窗口条件下的验证 | 所有设备和系统版本的通用参数 |
| 团队设计基线 | 无实测数据时的设计和高保真参考 | 官方硬件规格、已经验证的实际值 |

实际验证以当前窗口数据为准，但不因此覆盖或删除机型文档中的官方参考值。二者应保留各自的来源、日期与适用条件。

## 9. 不从断点直接推导布局策略

断点只表达当前可用空间的类别，不表达业务内容，也不直接决定侧边导航、分栏、列表列数或居中限宽。

相同尺寸窗口应采用一致的响应式判断口径；具体布局仍结合原工程、页面语义及已确认方案。同一个 lg 窗口可以来自平板、阔折叠或三折叠，不能只对 tablet 启用宽屏逻辑。
