# 设备分类与形态

适用范围：本知识库中的直板机、折叠屏和平板设备。
核验日期：2026-11-02。

本文统一设备信息的记录方式，不规定页面导航、列表列数或分栏方案。具体机型的尺寸和能力查对应设备文档，不在公共规则中重复维护。

## 1. 设备类型与折叠类别

下列名称是知识库分类约定，不是 HarmonyOS 系统 API 枚举，也不要求修改测试工具已有的字段。

| 设备类型 | 含义 | 折叠类别 |
|---|---|---|
| `phone` | 直板手机，包含宽比例直板手机 | 不填 |
| `foldable` | 具有折叠屏幕的手机 | 按下表填写 |
| `tablet` | 平板设备 | 不填 |

| 折叠类别 | 含义 | 常见表述 |
|---|---|---|
| `standard` | 常规大折叠，单铰链、两个展开区域 | 大折叠、普通双折叠 |
| `wide` | 阔折叠，展开屏幕比例不同于常规大折叠 | 阔折叠、胖折叠 |
| `small` | 小折叠，通常沿机身纵向开合 | 小折叠、竖向折叠 |
| `trifold` | 三折叠，双铰链、三个展开区域 | 三折叠 |

分类以具体产品资料为依据，不按机型名称关键词或当前窗口宽度自行确认。宽比例直板机不是阔折叠；折叠设备合上后，也不会变为 `phone` 类型。

本知识库不收录 PC/2in1 适配规则。不认识的设备类型应说明未收录，不能自动归为直板机。

## 2. 不要混用六类信息

| 信息 | 表达什么 | 示例 |
|---|---|---|
| 设备类型 | 产品属于哪类设备 | `foldable` |
| 折叠类别 | 折叠产品的结构或比例类别 | `trifold` |
| 使用形态 | 当前使用的屏幕区域组合 | F、N、M、LM、RM、G |
| 物理折叠状态 | 设备的折叠姿态 | `FoldStatus` 返回值 |
| 屏幕显示模式 | 系统报告的显示模式 | `FoldDisplayMode` 返回值 |
| 窗口状态 | 当前应用实际获得的显示空间 | 方向、窗口宽高、全屏、分屏或自由窗口 |

上述信息不能相互替代。例如，同一物理状态下可能出现不同应用窗口；相同窗口尺寸也不能证明物理姿态相同。

## 3. 使用形态如何记录

每个机型使用官方形态名称，并在设备文档中逐行记录，不统一压缩成“折叠／展开”两种。

| 产品范围 | 官方指南中的常用形态 |
|---|---|
| Mate XT、Mate XTs | 单屏 F、双屏 M、三屏 G |
| Mate XT 2 | 单屏 F、单屏 N、双屏 LM、双屏 RM、三屏 G |

来源：[三折叠应用开发](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-matext-guide)。表中仅列形态名称；尺寸、方向和相机差异由各机型文档维护。

- 同为单屏的 F/N、同为双屏的 LM/RM 不能因类别相同而合并尺寸。
- 某机型没有收录的形态，不从同系列其他型号复制。
- 形态代码只在对应机型及来源的语境中使用，不当作跨机型通用枚举。
- “单屏／双屏／三屏”描述显示形态，不表示页面必须显示一栏／两栏／三栏。
- 内外屏名称按实际结构记录，不能假定所有折叠设备都有相互独立的内外两块屏幕。

## 4. 物理折叠状态与显示模式

物理状态通过 `display.getFoldStatus()` 查询；显示模式通过 `display.getFoldDisplayMode()` 查询。具体可用枚举和接口版本按工程 SDK 与官方 API 文档核对。

三折叠的两处折叠区域分别有折叠、半折、展开三种状态，形成 3×3＝9 种组合。这九种物理状态与常用使用形态不是同一张表，不能按数量或名称强行一一对应。

官方《三折叠应用开发》的九种状态与显示模式对照表以 Mate XTs 为例，不能直接作为 Mate XT 2 的映射依据。

记录映射时，必须明确机型、使用形态、物理状态、显示模式及依据；实测还应注明系统版本和采集条件。没有可靠来源时明确“映射未核验”，不自行补齐。

## 5. 半折、悬停与设备能力

半折是物理状态；悬停是设备支持的使用能力，两者不等价。

- 不能因设备存在半折状态，就声明它支持悬停专属体验。
- 官方明确 Mate XT 2 不支持悬停态，应作为机型能力限制记录，不能继承其他 Mate XT 系列的悬停方案。
- 相机、手写笔和多窗能力也应按机型及适用条件查询，不由屏幕大小或折叠类别推断。
- “功能可用但不推荐使用”“官方未公开”“尚未核验”“明确不支持”应分别表述。

来源：[三折叠应用开发](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-matext-guide)。

## 6. 方向与窗口状态

| 信息 | 记录方式 |
|---|---|
| 横竖方向 | `portrait / landscape`，拼写固定 |
| 反向方向 | 需要区分时补充系统方向枚举，不能只靠宽高表示 |
| 屏幕旋转 | 保留原始旋转枚举及其含义，不将枚举数字直接当成角度 |
| 窗口模式 | 明确全屏、分屏或自由窗口等实际场景 |

参考方向只是机型规格表的记录姿态，不表示该形态只能采用此方向。相同屏幕旋转值在不同设备或形态下，不应被默认解释成相同显示方向。

物理形态、显示方向、窗口模式和布局断点分别记录。尺寸及断点的解释见[尺寸单位与断点](尺寸单位与断点.md)。

## 7. 查询与使用边界

先确认具体机型与版本，再查询本次需要的使用形态、尺寸或能力。型号不明确时，不用系列规格替代精确型号。

普通布局依据实际窗口或容器尺寸与已确认方案处理；只有悬停、折痕分区等依赖物理姿态的场景，才额外使用折叠状态及对应能力。

知识库分类不自动决定任务测试范围，也不自动扩大高保真预览数量。任务和测试仍按调用方明确的范围执行。
